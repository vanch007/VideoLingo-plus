# VideoLingo-plus Project Notes

## Stack

- Python 3.10 conda env: `videolingo`
- Streamlit UI entry: `st.py`
- Core pipeline modules: `core/step1_ytdlp.py` through `core/step12_merge_dub_to_vid.py`
- Shared pipeline engine: `core/pipeline/`; CLI entry: `core/cli.py`
- Provider contracts/adapters: `core/providers/` for LLM/TTS/ASR-quality contracts, oMLX discovery, MLX TTS routing, ASR readback, and dubbing repair plans.
- Runtime context helper: `core/runtime_context.py` reads `output/pipeline_state.json` first, then config, so repair/rewrite/TTS/readback use the current run's source/target language when config drifts.
- Dubbing repair internals are split by responsibility: `core/providers/dubbing_repair.py` remains the public facade, with rule classification in `dubbing_repair_rules.py`, JSON/history helpers in `dubbing_repair_io.py`, and shared types/constants in `dubbing_repair_types.py`.
- Dubbing quality loop: `core/dubbing_quality.py` writes `output/audio/dubbing_eval.json` and `.xlsx`; `core/dubbing_rewrite.py` handles time-budget LLM shortening/expansion.
- Audio speed fitting lives in `core/audio_speed.py`; `core.step10_gen_audio` re-exports the public helpers for compatibility.
- Audio/video dependency: Homebrew `ffmpeg` with `libass`, `x264`, `x265`, `videotoolbox`
- ASR providers: stable-ts/MLX, WhisperX, FunASR
- TTS providers: local MLX IndexTTS2, Edge/Cloudflare Edge, VoxCPM, GPT-SoVITS, Piper, Indonesian VITS, local MLX router (`mlx-indextts2`, `mlx-omnivoice`, `mlx-qwen3-tts`, `mlx-voxcpm2`)

## Commands

- Start UI: `conda run -n videolingo streamlit run st.py`
- Shared CLI doctor/models/run/eval: `conda run -n videolingo python -m core.cli doctor`; `conda run -n videolingo python -m core.cli models list`; `conda run -n videolingo python -m core.cli run --input <video-or-srt> --source zh --target vi --profile cinematic --tts auto`; `conda run -n videolingo python -m core.cli eval dubbing`
- Local video smoke run: `conda run -n videolingo python -m core.cli run --input <local-video> --source zh --target en --profile cinematic --llm config --tts edge_tts --smoke-seconds 60 --no-resume`
- Inspect workflow state: `conda run -n videolingo python -m core.cli status`; add `--include-dubbing-eval` to include current dubbing quality summary.
- Inspect translation provenance: `conda run -n videolingo python -m core.cli translation status`; backfill trusted current artifacts with `python -m core.cli translation adopt-current --apply`; plan non-destructive reset with `python -m core.cli translation archive`, then add `--apply` only when old translation-derived artifacts should be moved to `output/history/translation_*`.
- Run a step: `conda run -n videolingo python -m core.step2_whisperX`
- Check environment: `conda run -n videolingo python -m core.doctor`
- Evaluate current dubbing timing: `conda run -n videolingo python -m core.dubbing_quality`
- Optional ASR readback eval: `conda run -n videolingo python -m core.cli eval dubbing --readback --limit 10`; omit `--limit` for full readback, add `--force` after scoring logic changes.
- Plan/apply failed-row dubbing repair: `conda run -n videolingo python -m core.cli repair dubbing --limit 20`; add `--reasons missing_audio,over_duration` to filter failure classes, `--actions slow_fit_existing_audio` to isolate a repair action, `--apply` to mutate selected rows, `--batches N` to repeat batches, and `--full-remap` to recompute chunk timing. Applied repairs rebuild `output/dub.mp3` and `output/AI配音.mp4` by default; add `--no-rebuild-output` only for fast intermediate repair loops.
- Clean output only when intended: `conda run -n videolingo python -m core.onekeycleanup`
- YouTube bot-challenge downloads: after user approval for Chrome cookies, use `VIDEOLINGO_YTDLP_COOKIES_FROM_BROWSER='chrome:Profile 1'`; the downloader also enables Node/EJS remote components when Node is available.

## Configuration

- `config.yaml` stores non-secret defaults.
- Secrets must come from environment variables listed in `.env.example`.
- Current default workflow is Chinese source to Vietnamese target, stable-ts MLX ASR, and local MLX IndexTTS2 dynamic cloning.
- Independent parody/redub workflow lives in `/Users/vanch/skills/video-redub-creator`; it prefers stable-ts word timestamps for source subtitles/timeline, Demucs for separation, `/Users/vanch/mlx-indextts2` for cloned-voice TTS, and Qwen3-ASR for final readback.
- Classic-line parody redubs should run with `--strict-rewrite-sync`: the skill writes `rewrite/source_rewrite_profile.json` and `rewrite/rewrite_sync_report.json`, preserves source timings by default, and rejects missing/overlong rewritten lines before TTS when strict mode is enabled.
- Full-video parody redub validation artifact: `/Users/vanch/VideoLingo-plus/redub_runs/e0c803SQrss_full_video_grouped_v7_patch/redub-20260607-100249-v7patch/redub_video.mp4`; Qwen3-ASR readback passed `20 ok / 0 warn / 0 fail`, source duration `170.814s`, final MP4 `170.796s`.
- `dubbing_quality.mode: high_sync` enables duration budgets, measured rewrite/retry, strict eval, and absolute-timeline audio overlay.
- `llm.provider: openai_compatible` is the default translation route and reads `api.base_url` / `api.model`; oMLX remains optional and should not be used for translation quality tests unless explicitly selected.
- LLM translation stages write `output/log/llm_artifacts_manifest.json`; `core.cli translation status` compares stage logs and manifest against the current configured model to prevent old oMLX/config-provider artifacts from leaking into dubbing.
- CLI `run` / `resume` blocks when stale translation artifacts would feed downstream steps; use `--auto-archive-stale-translation` only when moving stale derived outputs to history is intended.
- CLI `run --dry-run` is non-mutating: it reports planned config updates and pending steps without writing config or `output/pipeline_state.json`.
- CLI `resume --run-id <id>` reuses the stored input and run options from `output/pipeline_state.json` when explicit arguments are omitted.
- CLI run config precedence is profile first, then explicit CLI overrides; `--tts edge_tts` stays effective even with `--profile cinematic`, while `--tts auto` resolves to local `mlx_indextts2`.
- `--smoke-seconds` trims local video imports only; URL inputs continue to use `smoke_test.enabled/cutoff_seconds`.
- `tts_method: mlx_indextts2` forces local IndexTTS2 dynamic voice cloning; `tts_method: mlx_router` auto-routes Vietnamese to IndexTTS2 and Chinese dialogue to OmniVoice unless a backend is forced.
- `dubbing_quality.asr_readback_backend: builtin` uses cached local stable-whisper/MLX for ASR readback; `backend: command` can use `dubbing_quality.asr_readback_command` with `{audio}` and `{language}` placeholders.
- Dubbing eval separates `asr_readback_configured` from effective `asr_readback`; when the command template is empty and no score columns exist, ASR readback remains unverified instead of showing a false pass.
- ASR readback cache is fingerprinted by target text, source reference, runtime target language, backend/model or command, and segment audio signatures; stale score columns are recomputed automatically when any input changes.
- Vietnamese readback scoring normalizes number words such as `mười chín` against ASR digits such as `19`, and reference-leak scoring ignores shared numbers when the source reference is Chinese.
- Dubbing repair writes `output/audio/dubbing_repair_plan.json`, appends batch records to `output/audio/dubbing_repair_history.jsonl`, prioritizes missing audio before warnings, and only mutates audio/tasks when `core.cli repair dubbing --apply` is explicit.
- Under-duration repair is distinct from over-duration repair: negative end drift beyond `dubbing_quality.max_early_end_drift` is treated as short speech, can slow-fit existing audio within `dubbing_quality.slow_fit_min_speed`, and falls back to expand/regenerate when stretching would sound unnatural.
- Natural speech repair treats `dubbing_quality.max_natural_speed_factor` as a hard warning line: fast rows are shortened/regenerated before accepting accelerated audio, and `under_duration_fit_margin_seconds` gives slow-fit a small safety margin against boundary drift.
- `step10_gen_audio.process_row` passes the current `row_available_duration` into TTS adapters instead of stale `target_duration` columns, so duration-aware backends do not truncate numeric-dense lines.
- When repair mutates audio, stale `asr_*` score columns are cleared so subsequent quality gates do not reuse old transcripts.
- Step11 audio merge fails fast on missing/corrupt segment audio unless `dubbing_quality.allow_silence_fallback` is explicitly enabled.
- Over-duration triage writes `output/audio/dubbing_over_duration_report.json` and classifies rows as speed-fit, rewrite/regenerate, or manual timeline/script review.
- Timeline rescue writes `output/audio/timeline_rescue_report.json` / `.xlsx`; `core.cli rescue timeline --write-candidate-tasks` can create non-destructive `output/audio/tts_tasks_timeline_rescue.xlsx` from the current fixed timeline.
- LLM provider clients use `llm.timeout_seconds` / provider `timeout_seconds` so local oMLX waits do not hang repair loops indefinitely.
- Repair-time LLM rewrite uses `dubbing_repair.llm_timeout_seconds`, `llm_retry_attempts`, and `llm_retry_interval` so small repair batches fail fast instead of inheriting long global translation retries.
- Repair-time LLM rewrite uses independent `dubbing_repair.max_rewrite_rounds`, and unchanged rewrite output is treated as a skipped/manual-review repair instead of a successful regeneration.
- English ASR-low repair can fall back row-by-row to `edge_tts` via `dubbing_repair.low_content_fallback_backend`, and row-level `tts_method` overrides are honored by `tts_main`.
- English repair rewrite rejects wrong-language LLM output before writing task rows; if a compact English fallback is available it uses that, otherwise the row becomes manual review.
- Quality eval reports exhausted automatic repair rows as explicit `manual_review` warnings with `manual_review_reason`, instead of repeatedly planning no-op repairs.
- Generated-silence trimming is disabled by default with `dubbing_quality.trim_generated_silence: false` because it shortened local IndexTTS2 English smoke rows below their timing windows.
- Expand-time LLM rewrite uses a word budget and retry guard so short segments are not padded into overlong scripts.
- Local MLX TTS adapters run from their own backend repos, so VideoLingo audio input/output paths must be passed as absolute paths.
- `step5_splitforsub` writes split rows for subtitles but keeps `translation_results_remerged.xlsx` at original-row granularity for dubbing; target-language joiners must preserve spaces for Vietnamese.
- `step6_generate_final_timeline` keeps fuzzy ASR alignment local and consumes the current word cursor on fallback to avoid repeated livestream phrases pulling timestamps far into the future.
- `clean_text_for_tts` preserves punctuation that changes speech meaning, especially numeric ranges and slash compounds such as `1-10` and `to/lòng`.
- Test dependencies are isolated in `requirements-dev.txt`.
- Tests that apply repair plans must monkeypatch destructive audio deletion or point segment paths at temp dirs; do not let unit tests mutate `output/audio/segs`.

## Maintenance Rules

- Do not delete `output/`, `history/`, voice samples, or dirty worktree files unless explicitly requested.
- Add new ASR/LLM/TTS backends through registries/adapters instead of hard-coding branches in UI code first.
- Keep TTS method metadata in `core/all_tts_functions/tts_registry.py`; UI and step code should read registry helpers instead of duplicating method lists.
- Keep batch and Streamlit workflows using the same core modules.
