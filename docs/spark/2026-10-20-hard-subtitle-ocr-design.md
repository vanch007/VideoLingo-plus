# 硬字幕 OCR 辅助纠错与替换设计

日期：2026-10-20。状态：设计草案，待用户审阅；尚未实施，不代表模型准确率或视觉效果已验收。

## 1. 目标、边界与推荐

为有画面硬字幕的视频提供两个可独立启用的功能：

1. 从画面取得带时间和来源证据的文字，辅助发现、修正 ASR 错误，并辅助翻译专名核对。
2. 定位硬字幕出现的位置和时间，在生成新字幕时遮住旧字幕，减少双层文字干扰。

推荐“轻量变化检测 + 本地 OCR + 音画交叉校验 + 分时段稳定遮罩”。默认关闭，用户为当前视频启用后执行；同一公共流程服务 CLI、Streamlit、Fast 和标准模式。

| 路线 | 优点 | 局限 | 选择 |
| --- | --- | --- | --- |
| 少量抽帧、固定区域 | 最简单、耗时少 | 无法覆盖全文；容易长时间遮挡无字幕画面 | 仅作初步定位和用户手动区域方案 |
| 变化检测、代表帧 OCR、分时段遮罩 | 兼顾覆盖、计算成本和可追溯性 | 需要检测、时间关联和缓存 | 本次推荐 |
| 逐帧大型 OCR、视频修复式去字 | 可探索更细定位和背景恢复 | 开销大；修复可能闪烁、改变景物；本机无对比证据 | 不纳入首版 |

首版覆盖稳定或分段变化的横/竖版对白字幕、单语/双语、换行、无字幕间隙。动态逐字特效、竖排滚动、复杂卡拉 OK 和大幅移动字幕应明确标为不支持自动处理，允许手动区域或关闭遮罩。台标、作者标识、弹幕和场景文字不属于默认去除对象。模糊/马赛克是遮挡，不是恢复原始背景或保证无痕。

## 2. 现有项目依据

- `core/pipeline/runner.py` 负责导入、转写、文本处理和输出阶段；任务使用独立工作区和产物清单。
- `core/step2_whisperX.py` 已有来源和识别配置指纹。`core/all_whisper_methods/local_aligned.py` 支持绑定原音频、匹配修改前原文的外部修订，再做强制对齐；目前该修订入口限制为 MOSS 分段凭据，不能直接假设其他后端已支持。
- `core/source_verification.py` 提供音频交叉识别证据；`core/source_accuracy.py` 提供文字评测。现有相似度分数不等同于纠错正确概率。
- 普通字幕、标准配音、快速配音分别由 `core/step7_merge_sub_to_vid.py`、`core/step12_merge_dub_to_vid.py`、`core/fast_video_merge.py` 输出。Step 12 在 Fast 下提前转入独立入口，必须覆盖三条路径。
- Fast 的 `core/fast_timing.py::time_map` 和合成中的时间变换需要一致；硬字幕使用源视频显示时间，新字幕使用对应的原声或配音时钟。
- OCR 技能：`/Users/vanch/.gemini/config/skills/ocr-recognition/SKILL.md`。本地 AX Unlimited OCR，固定模型版本、隔离运行时，不上传帧。模型文字、标签和坐标均需要校验。
- 本案例沿用前次调查：B 站视频无可下载 CC/内嵌字幕，口播为日语、画面有中日字幕；正式短测仍需保存对应源文件哈希和逐段证据。已有单帧实验不能证明全片质量。

## 3. 处理流程

```text
导入/下载 → 确定唯一源视频、方向、尺寸与时间基
                    ↓
         初步字幕区域探测 → 全片变化扫描 → 代表帧 OCR
                    ↓                         ↓
             字幕区域与出现区间         中/日等独立文字轨
                    ↓                         ↓
             遮罩计划候选         与原始 ASR 按时间关联
                    ↓                         ↓
                    │             复核差异 → 修订 → 音频重新对齐
                    │                         ↓
                    │                分句、翻译、新字幕/配音
                    └──────────→ 统一遮罩计划与最终合成
```

两条支路独立验收：位置可靠不代表文字正确，文字清楚不代表坐标精确。已有软字幕时仍可探测硬字幕；纯 SRT 输入没有视频则跳过 OCR，不伪造“未发现硬字幕”。

### 3.1 探测与变化扫描

- 以规范化、方向正确的源视频为唯一坐标对象；记录原视频到规范视频的变换。取帧使用解码时间戳，不能只用帧号除以平均帧率处理可变帧率。
- 全片均匀取 16 个初探帧，包含前、中、后段。底部为优先候选区而非硬限制；连续无有效候选、出现布局变化时扩大探测范围。
- 多帧结合行形状、文字内容变化、位置稳定性形成候选轨，区分双语行组。长时间不变的小标识作为疑似台标排除；不以“位置稳定”单独认定字幕。
- 初探后流式扫描低分辨率候选区域，起始目标为每秒 6 次轻量检测。使用文字笔画/边缘变化、行布局和周期性检查，避免把背景运动全部当作换字幕。该采样率不保证捕获所有短字幕，必须在短测中评估漏检。
- 只有变化事件、定期审计帧、布局重探和冲突复核触发大型 OCR。定期审计起始间隔为 2 秒，避免变化检测漏报后长时间失察；必须记录没有检查的区间。
- 每个事件选择清晰代表帧；关键差异补 1–2 帧。相同文字但不同时间出现仍保留独立事件，不能全局去重后丢掉重复台词。
- 出现/消失边界在相邻采样区间内加密取帧；非单调闪烁不能仅靠二分法。持续不稳定时标记待核对。
- 多帧几何聚类产生“布局段”；用有效框包络覆盖最长文字和双行，排除异常框后再加边距。聚合中位数可用于稳定中心，不能用中位宽度裁掉长句。

### 3.2 本地 OCR 与轨道结构

- 使用指定 OCR 模型和固定版本；一个独立工作进程加载一次，批量处理裁剪帧。复用技能实现与固定提示，项目只封装视频调度和输出适配，不复制维护另一份模型推理栈。
- 模型缓存解析不硬编码某台机器的 snapshot 绝对路径；验证本地版本和文件存在。默认离线，运行时缺失返回可操作错误，不静默改用云端或自动更换模型。
- OCR 进程与大型 ASR/TTS/LLM 顺序使用内存。完成 OCR 后释放模型；冲突回查集中为一个有界补充批次，不能逐句重复冷启动。
- 解析原始模型响应，验证坐标尺度、范围、行顺序；从模型坐标经裁剪缩放逆变换回规范视频像素。记录原始框与最终框，禁止凭空修正异常框为“成功”。
- 每条事件保存文字、语言候选、显示区间、行框、布局段、代表帧、可复核证据。中日共享汉字的短句允许语言 `unknown`，不能强行分类。
- 文本质量、几何质量、语言判断、时间边界各自记录；多帧一致只是证据，不能包装成“95%正确概率”。

### 3.3 ASR 辅助纠错与翻译参考

- 原始音频 ASR 独立运行，保存不可变原文；第一轮不喂入 OCR，保留用于交叉比较的独立观察。
- 根据时间重叠和局部内容建立多对多关联，允许字幕早显、晚消、合并或拆分口播。不能按行号强行一一对应，也不能跨多个场景寻找相似词替换。
- 同语言字幕可提出修订；翻译字幕只作语义/专名参考。当前案例日文核对日语 ASR，中文核对中文译文。无法识别语言或字幕属概括时只报告差异。
- 首版默认 `review`：生成原 ASR、OCR、音频片段和候选修订对照；核准的修订经现有来源匹配和重新对齐入口应用。ASR 修订提交会使对应下游文本/配音凭据失效，不能沿用旧声音冒充新稿。
- 可配置 `verified_auto`，但仅在短测通过后开放自动应用：同语言、多帧文字一致、局部盲听音频识别支持候选、修改范围明确、无数字/否定/主体关系歧义。盲听复核不提供 OCR 候选，避免循环证明。
- 数字、否定、人物关系或多证据冲突进入待核对；无音频支持的 OCR 不自动覆盖 ASR。强制对齐成功只证明时序可对齐，不证明文字正确。
- 修订账本包含 before/after、源视频/音频哈希、原识别片段身份、OCR 事件、声音证据、修改来源和状态；自动规则通过与人工确认分别标记。
- MOSS 复用现有修订入口；其他 ASR 后端需通过同一结构适配和回归测试后才能应用，未支持时仅输出对照，明确能力缺口。
- 高频地名可进入带来源的术语候选，不直接写入全局词库。画面文字是数据，不作为模型指令执行。

### 3.4 遮罩与新字幕合成

- 候选区域按布局段固定边界，时间按字幕实际显示区间启停，避免逐字或逐帧跳动。独立中日轨同时存在时可合并相邻框，但不随意盖满底部整条画面。
- 默认局部模糊；提供马赛克和实色底板。参数按最终画面尺寸/文字高度缩放，不能将 1080P 的固定半径直接套到 4K。
- 模糊可能留字影，马赛克也可能仍可辨认；实色底板覆盖最可靠但遮挡最明显。首版生成同一片段的三种预览，不自动将低质量模糊切换为更大黑条。
- 默认要求开启新字幕烧录，存在已验证且属于本视频的新字幕和对应内容，再启用遮罩。只有软字幕导出或新字幕缺失时不遮。
- 原硬字幕和新字幕显示区间未必完全一致：先在源时钟核对替代内容，再映射成片时钟；短小边界差可在既有显示规则允许范围内延展新字幕，不能改变配音或挤占邻句。不允许无替代内容却自动抹掉原文字。
- 无法合法覆盖的区间保留原画并标记未替换；若用户要求完整替换交付，这些区间必须解决后才能验收，不能把部分成功当成完成。
- 渲染顺序：方向/画幅规范化 → 源时钟上的旧字幕遮罩 → 必要的视频时间变换 → 新字幕烧录 → 编码。先遮罩后变速可让遮罩自然跟随原画面，避免重复套用时间映射。
- Fast 的新增替代覆盖检查使用唯一 `time_map`；跨延长区间拆分评估，补尾克隆帧需同步检查有无残留遮罩。标准路径使用恒等映射。
- 文字排版读取现有完整词/行宽/双语规则，把遮罩区域作为布局约束；装不下时重新布局或报告冲突，不截字、不任意压小字号。
- 三条渲染入口共享计划验证和滤镜构造。遮罩尽量并入既有视频编码，不新增全片中间有损转码。
- 区域数多时按布局合并区间，通过滤镜脚本传递，避免超长命令行；仍超过已验证复杂度时分段处理并验证接缝，不静默截断计划。

## 5. 产物与缓存契约

当前任务工作区内 `output/hard_subtitles/` 保存：

- `source.json`：唯一源身份、方向/尺寸、时间基、模型版本、参数与代码指纹。
- `events.jsonl`：可追加的事件记录，状态为 pending/pass/fail/needs_review；非零退出不能写为成功。
- `tracks.json`：独立语言轨与布局段；含实际观测范围和未决区间。
- `ocr.<lang>.srt`：便于阅读的 OCR 字幕导出，明确为识别结果而非官方原字幕。
- `source_review.json`：候选和已接受修订的完整证据账本。
- `mask_plan.json`：源时钟区域、原字幕区间、替代关联、输出变换身份、处理方式。
- `evidence/`：代表帧与必要复核裁剪，不保存所有解码帧；保留修订所依赖的图片。
- `preview/`：短片对比；`report.json`：覆盖、未决项、耗时、峰值内存与验收状态。

事件至少包含 event_id、track_id、layout_id、source_start/end、boundary_uncertainty_ms、text_raw/normalized、language/status、bbox_px、frame_pts、evidence_paths、quality_flags。缺失文字允许为空但不能当正确结果；空字幕画面与 OCR 失败分开记录。

缓存键绑定源哈希、实际取帧时间、方向/裁剪/缩放、模型/提示/解析器版本。分层失效：遮罩样式变化只重渲染；修订变化才重对齐及依赖的文本/声音；模型变化重 OCR；视频变化全部拒绝旧缓存。参数不同的失败重试有账本，续跑不能重置重试预算。文件原子写入并服从现有工作区锁。

## 6. 用户操作与默认配置

界面只暴露必要选项：

1. “视频含硬字幕”：启用分析，展示发现的语言轨和位置。
2. “辅助校对原文”：默认对照审核；自动修订为单独选项，需满足验证条件。
3. “替换原画面字幕”：默认局部模糊，可切马赛克/底板；预览中允许调整区域和排除非字幕文字。
4. 结果区显示已检查范围、待核对数量和短片预览。调整区域只影响当前视频，不覆盖全局配置。

拟议内部起始参数：enabled=false；initial_samples=16；scan_fps=6；audit_interval_seconds=2；max_extra_ocr_frames_per_event=2；source_correction=review；mask_mode=blur；replacement_required=true。均为短测起点，非已验证最优值。布局识别阈值经短测校准，以明确的证据条件和观测比例展示，不设虚假的统一置信概率。

用户关闭功能时保持原流程；运行失败默认记录后停止该功能，不自动遮罩。可选择带告警继续原 ASR/无遮罩导出，但该输出不得标记“硬字幕已替换”。纠错与遮罩可分别成功或失败。

## 7. 验收与短测设计

先从当前 B 站源视频挑选合计约 2–3 分钟的代表片段，人工标注至少 40 个字幕事件，覆盖中日双行、换行、长句、快速切换、运动背景、无字幕和台标附近文字；真实素材缺少的条件用独立测试夹具补充，并区分证据来源。开发集与保留验收片段分开，不能调参后在同一批样本宣称泛化。

以下是拟议发布门槛，当前全部 pending：

| 项目 | 验收要求 |
| --- | --- |
| 字幕事件覆盖 | 按语言轨独立核算召回率 ≥95%；所有已知漏检保留记录；无字幕负例不生成启用遮罩 |
| 文字质量 | 对人工逐字标注的同语种原画面文本，规范化 CER ≤5%；报告标点处理方式与专名错误，不能将 OCR 与 ASR 一致作为真值 |
| ASR 改善 | 与同一段原始 ASR 比较，错误基线存在时修订后 CER 下降；基线无错时保持不变；保留样本无新增错误修订，关键事实错误修订为 0 |
| 时间边界 | 参考实际帧 PTS，边界误差 P95 ≤100ms；明显闪烁/短字幕单列，不用平均值掩盖 |
| 遮罩视觉 | 验收片段人工逐事件检查：旧字含描边完整覆盖，无误遮台标/其他文字；新字完整，无双层残字、突跳及无字幕区间持续遮罩 |
| 音画同步 | 恒等和 Fast 多处延长均检查接缝、尾部；无遮挡偏移，不改变已经验收的声音内容与混音规则 |
| 续跑 | 中断恢复不丢已成功事件；相同配置复用；样式变化 0 次新增 OCR/ASR/TTS |
| 故障安全 | 模型缺失、空响应、异常框、语言 unknown、错视频缓存、缺新字幕均不能产生错误“成功”状态 |
| 性能 | 报告实际墙钟时间、OCR 调用数、峰值内存和缓存命中；有界队列、不缓存全片图片、不逐事件加载模型；不预先承诺倍速 |

单位测试用固定事件/框和伪 OCR 输出，覆盖坐标逆变换、重复句不误合并、双语语言不明、区域切换、边界精化、缓存、修订来源匹配和缺失替代内容。合成测试需真实生成短片，覆盖竖版、旋转、4K 坐标、可变帧率和 Fast 时间延长，验证实际画面而不只验证滤镜字符串。

自动“模糊后 OCR 读不到字”不能单独证明视觉质量：人眼可能仍见字影；遮罩参数需结合短片对比审核。单视频验证仅支持该类素材结论，不承诺所有平台或所有字幕样式。

## 8. 范围收敛与交付界限

首版必须交付：独立文字轨、可核对的 ASR 差异/修订入口、稳定区域与显示区间、三条输出路径的局部遮罩、新字幕合成、缓存续跑与短片验收。不能用只生成关键词或只画一个固定框代替完整功能。

不包含：自动修复背景、删除台标、水印去除承诺、逐字动态字幕精确还原、重新训练 OCR、全库技能修改、无关 Fast 缺陷修复。当前设计不改现有质量门槛，也不证明旧管线的所有历史问题已解决。
