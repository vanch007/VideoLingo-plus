# 本地翻译与配音现行流程

本流程由项目 `config.yaml`、共享 CLI 和 Streamlit 的正常步骤执行。案例验证脚本只用于复查产物；新视频直接进入正常流水线。

## 默认路线

| 阶段 | 现行规则 | 实现入口 |
| --- | --- | --- |
| 识别与时间 | 原始无损音频由本地 MOSS 转录，Qwen 单独强制对齐；保留原句、标点和重复内容 | Step 2–3 |
| 对话理解 | 按上下文推断每句角色、对象和转述关系，同时保留声学说话人证据；不确定角色不能补充原句没有的事实 | Step 4.1 |
| 主翻译 | 本地 Index-Translate 结合术语和角色上下文翻译，检查原句事实与重复内容 | Step 4.2 |
| 配音可用性 | 翻译阶段预合成自然语音并回读，实测时长后验收；允许的最高加速为 1.08×，含边界值 | Step 4.2 |
| 中/英时长候选 | 完整且回读通过的自然语音超时时，Homura 按实际朗读成本和实测音节目标提供候选；Index 再核对原文语义，重新合成和测量 | Step 4.2 |
| 台词与语音锁定 | 验收绑定台词、源时间、声音设置及自然/适配音频哈希；配音阶段复用这些结果。完整短语音保持自然速度，用静音填充剩余窗口 | Step 4.2、8–10 |
| 双语显示 | 对原文和译文做精确顺序覆盖的语义配对，保留完整词语、专名、金额和必要动作短语；显示切分不改变配音单元 | Step 5–6 |
| 字幕时钟 | 原音视频使用源语言词时间；配音视频使用实测目标语言词时间。每对双语共享起止时间 | Step 6、11 |
| 导出 | 校验当前配对、文字、词时间、字幕文件及语音锁定证据；不一致时停止导出 | Step 7、12 |

字幕上限由同一显示契约计算：英文每行至多 42 字符、中文每行至多 22 字符，同时服从配置中更小的限制。每种语言按 `subtitle.max_lines` 使用一至两行；先确定完整语义片段，再验证实际换行的行数和每行长度，不将单行限制误当整个语义片段的限制。无法在两行内排下的片段仍须按时间分切，不能截字。空间限制与阅读速度分别检查：满足行长不代表 CPS 合格。不能用重复整句、按比例切原文或删去意思代替语义对应。

翻译候选在合成声音前先验证双语分切可行性。语序重排导致无法逐段对应时，按源文词语和语法边界分段，使用 Index 原生翻译请求生成对应候选，再做局部对应和整句含义审核。片段合为完整台词才进入 TTS；字幕片段不是独立配音任务。导出时再次绑定实测词时间。超长、漏字、错位不得以整句回退或截取前两行通过。

相同文案只需一份完整语义审核证据：初译、时长调整和最终发布共享 `source_semantic_receipts`，按精确源文、译文、上下文、语言、模型和审核代码绑定。任何一项变化、记录损坏、审核未完成或被拒绝，都不能复用。英→中的盲回译与双向事实比较仍保留；最终发布校验当前证据，不能用声音通过代替语义审核。

盲回译也是辅助模型输出。它与源文有分歧时，先独立比较目标译文和回译的对应事实；确认回译本身失真，才允许一次只依据目标译文的回译修正，再重新比较源文。不能把源文答案注入回译，也不能以复核投票替代事实证据。缺少所有者、备选品牌、时序、数量或不确定性等实质内容仍须拒绝；确认错误的文案通过正常重译和声音预检查后才能替换，正确文案继续复用原声音。

辅助回译修正只接收完整当前译文，不携带失败回译或原审核猜测，避免反复复制错误时态。原文与回译比较若返回虚构引用，只允许一次明确分栏的结构恢复，仍按真实源文逐字校验；相同无效请求不重复发送。源文明确的列表编号（如“Job three”）与同编号序数表达表示同一项，其名词类别来自实际源文。中文分类句没有英语冠词词形，辅助回译的the/an变化本身不能证明换了角色；真实对象、类别、编号、明确限定、否定和时间变化继续拒绝。

字幕切点先做确定性处理：相邻的破词或单字碎片在原文和译文中同步合并，仍保留精确文字覆盖和原有行长上限。合并后的新对应关系继续做语义审核，声学时钟到位后再核对同步。同一组已经拒绝的切点不反复请求模型投票；纠正请求若再次返回相同无效答案和原因，则停止该请求序列并交给既有的有界恢复流程。实际请求（包括失败）的次数、耗时和结果记录在 `output/gpt_log/request_events.jsonl`。

源文切点搜索同时满足实际换行行数，不能只乘算字符总量。独立显示的专名片段只有在整句 NLP 判为专名、且译文词序与拼写逐字等同时可保留原文；其他片段和组合整句继续检查目标语言，逐对语义和整句审核仍为必需。

审核意见也是模型输出，不能成为新的源文事实。语义反馈重译达到有限次数仍失败时，清除这轮审核意见和旧译文提示，按源文顺序重新产生对应候选；仍重新检查源文事实、逐段对应、整句语义和实际声音。恢复失败保持拒绝，不能以重复审核、增加速度上限或删词通过。

源句如果是前一片段接续的名词、定语或目的成分，只按同一声学说话人的确切源文依存关系消歧，不把前句的独立事实补入当前片段。独立分句的信息顺序仍保留，分句内部允许目标语的自然语序。名词描述不能被审核或重译改成两个独立断言；祈使引导语按言语目的理解，实际操作、否定和条件仍逐项核对。

语义修复不等于已经超时。没有实测超时证据时，提示只要求恢复完整源意，不虚称旧稿超时；有限反馈重译失败后先尝试不带失败译文的完整源句恢复，仍需当前语义及双语分切通过。该恢复不使用猜测的字数压缩代替保真；后续真实声音继续服从1.08×、0.12s、完整回读、专名与同步门禁。

审核运行失败不等于译文语义失败。审核输出截断、结构校验耗尽重试或暂时不可用时，只对同一源文与译文尝试一次简短审核，继续执行完整事实与原字引用检查；无法取得有效结果则保持未验收，不把错误信息当作重译指令。认证或请求参数错误直接报告。逐句修订保存为未验收草稿，续跑重新检查各门禁，进度分别显示“开始检查”和实际通过/待复核结果。

ASR 的原始句子、空格和标点是文字依据，强制对齐只提供时钟。跨越识别句界的塌缩词会触发逐句音频重新对齐；不得借邻句时间改写原文。缓存校验在日志锁外运行，校验不通过的旧结果保留诊断并重新生成。

强制对齐与独立 ASR 复核的相邻裁片都限制在共有边界内，不能因上下文填充重复带入邻句。未翻译词检查保留连字符术语；术语表只豁免完整拼写。JSON 和纯文本候选的重试均携带拒绝结果及校验原因。

最终媒体检查音画起点偏移、逐轨对比原片时长，并检查是否新增音画尾部偏差，误差仍以一视频帧或音频编码包为上限。原片音轨比画面长的尾部不要求通过剪掉声音来消除；最终音轨仍必须覆盖完整画面，不能因原片音轨较短而豁免缺尾。没有有效原片基准时不能据此放行。

Homura 负责中/英时长候选，主翻译和最终源文语义审核使用 Index-Translate。中文路径有本机短样本证据，官方没有公开中文基准，不能推断普遍效果。未通过语义、完整回读或时长验收的候选不能进入下游；下游不重新翻译已锁定台词。

本地 TTS 子进程启动前执行统一内存交接（`mlx_tts.release_omlx_before_synthesis: true`）：检查当前配置的本地 oMLX 主翻译/候选模型，确认空闲后卸载并核对状态；服务保持运行，后续文本推理按需加载。该入口也覆盖翻译阶段的预合成和重试，不只覆盖 Step 10。忙碌、状态未知、置顶、远程或分布式模型不卸载；管理失败明确记录，不能冒充已释放。记录位于 `output/log/omlx_memory_events.jsonl`。同进程请求与合成互斥，外部应用不共享此锁。本轮[自动卸载实测](../history/I%20Fully%20Automated%20My%20Video%20Editing%20Using%20Claude%20Code%20(Full%20Walkthrough)/evidence/full-memory-handoff.json)与[按需加载实测](../history/I%20Fully%20Automated%20My%20Video%20Editing%20Using%20Claude%20Code%20(Full%20Walkthrough)/evidence/full-demand-reload.json)已归档；正常推理可重新加载释放后的模型。

缺失或失败的声音回读必须拒绝，不能进入文本正则比较或复用旧成功成绩。回读结果先保存，再执行完整内容门禁；代码策略变化使验收凭据失效时，按音频/参考/文本/生成设置的真实身份复用自然候选并重新验收，不能通过重写manifest绕过，也不必重新合成身份一致的声音。

恢复时先找声音哈希绑定的完整文案，未发声的修订稿不能自动替代它。跨短验证与完整运行的同文案自然候选可复用不同种子的现有文件；参考、实际音译、生成环境和音频哈希必须一致，并重新拟合与回读。语义确有缺陷的旧文案仍须修正，声音回读通过不能豁免漏义。

源语义审核在翻译阶段完成，CLI和Streamlit共用`core.atomic_dubbing.translation_speech_preflight`。明确所属关系、概率、频率与独立教学目标先做程序核查，模型不能覆盖这些冲突。完整且输入、模型、策略都匹配的审核收据可复用，发布阶段不重复请求；实际声音、内容与同步仍逐句检查。

辅助回译必须从完整实际中文独立生成，不能从孤立汉字或错误英语稿猜词义。争议复核只接收实际源文、实际译文及待核片段；每一异议都需引用确切证据。源词义消歧最多一次，消歧之后仍执行完整实际译文复核。格式错误、空值或服务失败不能当作译文有漏义的证据，也不能据此改词和重新合成。

英文专名的显示与说话分开：原文拼写及出现次数由专名门禁检查，TTS使用登记的中文读法。术语可通过`translation.spoken_transliterations`或术语记录的`spoken`配置扩展；字幕不由声音回读中的中文音译反写。原稿确有源文证据的遗漏才替换声音，正确稿保持自然声音身份。

自然声音是否免于速度处理由实际毫秒窗口决定；近原速仍超出窗口时也须拟合。时长拒绝必须保留完整的当前回读音频，不能以缺文件误触发重新合成，也不能裁去可听尾部来通过。

## 正常入口与恢复

在项目根的 `videolingo` 环境执行；先检查运行环境和已有产物来源，再查看计划：

```bash
conda run -n videolingo python -m core.cli doctor
conda run -n videolingo python -m core.cli status --include-manifests
conda run -n videolingo python -m core.cli translation status
conda run -n videolingo python -m core.cli run \
  --input /absolute/path/source.mp4 --source zh --target en \
  --profile cinematic --llm omlx --tts mlx_indextts2 --dry-run
```

用户已授权生成且必需环境检查通过时，移除 `--dry-run` 执行。Streamlit 的“下载并配音”和“翻译并配音”通过 `core.pipeline.job.start_pipeline_job` 启动一次独立后台 CLI 调用，每个新任务在 `run_workspaces/<run_id>/` 保存配置副本、输出、日志和状态；刷新页面不中断任务。已安装模型与项目代码复用，旧输出不导入。工作区锁禁止两个进程同时写入，网页显示实际阶段和失败日志，并可恢复该工作区。

代码更新使分句、摘要、翻译或字幕文字检查点失效时，仅在来源、产物、配置与依赖哈希全部未变，且失效原因全为代码哈希变化时，正常续跑会把该文本检查点及旧清单保存到 `output/history/code_stale_checkpoints/<run_id>/`，真实执行对应生产阶段后再登记当前清单。该恢复保留媒体与自然声音缓存。数据或配置变化、缺失来源证据、失效的ASR检查点仍阻止自动恢复，并保存当前失败状态；不能重盖旧清单冒充执行。

当前项目根的旧 `output/` 存在历史 provider 产物，来源门禁会阻止直接复用；本次只清理用户指定的 `run_workspaces/`，没有归档或替换共享输出。保留的 V6 工作区常规 CLI 试运行通过。新任务先选择独立输出工作区，或在获得相应授权后归档旧共享输出。

字幕策略变化影响显示及合成阶段；台词、源时间、模型、声音条件或音频变化则需要重新完成翻译阶段的语音验收。不要通过重标“已完成”绕过来源、缓存或哈希检查。
